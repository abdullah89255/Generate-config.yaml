# Generate-config.yaml
## Usage

### From a single domain list

```bash
cd ~/Desktop/New_Folder
python3 mkconfig.py --program acme --domains-file data/domains.txt
```

The script copies `data/domains.txt` into `data/domains.txt` (same path if already inside `data/`) and writes `config/config.yaml` referencing it as a passive source named `seed`.

### Multiple named lists

```bash
python3 mkconfig.py --program acme \
  --list "subdomains:data/subs.txt" \
  --list "curated:data/curated.txt" \
  --list "ips:data/ips.txt"
```

Each source appears under `passive_sources:` with `enabled: true`.

### No passive sources

```bash
python3 mkconfig.py --program acme --no-passive-sources
```

Emits `passive_sources: []`.

### Overwrite safely

```bash
python3 mkconfig.py --program acme --domains-file data/domains.txt --force
```

Without `--force`, the script exits 2 and refuses to touch an existing file.

### Write to a custom location

```bash
python3 mkconfig.py --program acme --domains-file data/domains.txt \
  --output config/acme-config.yaml
```

### Override defaults

```bash
python3 mkconfig.py --program acme --domains-file data/domains.txt \
  --timeout-seconds 5 \
  --max-concurrency 1 \
  --requests-per-second 0.5 \
  --max-requests 100 \
  --log-level INFO
```

### Enable a module

```bash
python3 mkconfig.py --program acme --domains-file data/domains.txt \
  --enable-module headers --enable-module tls
```

## What the output looks like

Running this:

```bash
python3 mkconfig.py --program acme \
  --list "seed:data/domains.txt" \
  --list "extras:data/extras.txt" \
  --log-level INFO \
  --enable-module headers
```

Produces:

```yaml
# h1hunter application configuration
# Generated by mkconfig.py on 2025-01-15 for program: acme
#
# Copy is unnecessary; this is the working config.
# Credentials belong in environment variables, never here.

timeout_seconds: 10.0
max_concurrency: 2
requests_per_second: 1.0
max_retries: 2
max_requests: 200
max_response_bytes: 524288
output_dir: output
user_agent: "h1hunter/0.4 (+authorized-security-research; contact=you@example.test)"

logging:
  level: INFO
  format: console
  file: null

enabled_modules:
  - headers

passive_sources:
  - name: seed
    enabled: true
    options:
      type: text
      path: data/domains.txt
  - name: extras
    enabled: true
    options:
      type: text
      path: data/extras.txt
```

Drop `--log-level INFO` and `--enable-module headers` and it matches the example config you screenshotted.

## Field reference

| Field | Meaning | Conservative default |
|---|---|---|
| `timeout_seconds` | Per-request HTTP timeout | 10.0 |
| `max_concurrency` | In-flight requests cap | 2 |
| `requests_per_second` | Global token-bucket rate | 1.0 |
| `max_retries` | Retries per request | 2 |
| `max_requests` | Total budget for the run | 200 |
| `max_response_bytes` | Response size cap | 524288 (512 KB) |
| `output_dir` | Default output directory | `output` |
| `user_agent` | HTTP User-Agent header | h1hunter/0.4 |
| `logging.level` | Log verbosity | WARNING |
| `logging.format` | `console` or `json` | console |
| `logging.file` | Optional JSON log file path | `null` |
| `enabled_modules` | Pre-declared check modules | `[]` |
| `passive_sources` | Providers `recon passive` reads | (from lists) |

Note: `requests_per_second`, `max_requests`, `max_concurrency`, `max_response_bytes`, and `timeout_seconds` also appear in the **scope** file. When both are present, the scope file wins for active operations, because they are per-program constraints. The config-file values serve as fallbacks.

## Relationship to `mkscope.py`

| Script | Produces | Purpose |
|---|---|---|
| `mkscope.py` | `config/scope.yaml` | What you are authorized to touch |
| `mkconfig.py` | `config/config.yaml` | How the tool behaves + where it reads lists from |

They are independent. You can run either alone. Running both is the usual workflow:

```bash
# 1. Scope from the program policy
python3 mkscope.py --program acme --domain acme.test --force

# 2. Config with your seed list
python3 mkconfig.py --program acme \
  --list "subdomains:data/domains.txt" --force

# 3. Validate
h1hunter scope validate --file config/scope.yaml

# 4. Run passive recon
h1hunter recon passive --file config/scope.yaml --config config/config.yaml \
  --output output/passive.json
```

## Common mistakes

1. **Pointing `--list` at a directory, not a file.** `read_lines()` requires a file. Use `--list "name:/full/path/to/file.txt"`.
2. **Passing `name=path` instead of `name:path`.** The separator is a colon. On Windows, paths with drive letters work because the parser splits on the **first** colon only.
3. **Overwriting an existing `config.yaml` without `--force`.** Intentional; the script refuses.
4. **Expecting the config to grant scope.** It does not. Only `scope.yaml` does.
5. **Committing the generated `config.yaml`.** It is git-ignored. Keep it local.

## Summary

```bash
# One-shot: build a config from a list of domains
python3 mkconfig.py --program <name> --domains-file data/domains.txt
```

Or with multiple named sources:

```bash
python3 mkconfig.py --program <name> \
  --list "subdomains:data/subs.txt" \
  --list "curated:data/curated.txt"
```

The generated file is a drop-in for `config/config.yaml`, matches the shape of the example you screenshotted, uses conservative defaults, and stages your lists under `data/` so the tool finds them from any working directory. It never overwrites without `--force`, and it never touches the scope file — that remains `mkscope.py`'s job.
